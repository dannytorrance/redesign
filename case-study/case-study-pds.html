UX / Front-End Case Study

PDS Corporate Website & Excel Import Micropage

A trilingual corporate site and a Figma-spec'd data-upload tool, built from real company content and live design files to working code

Project Overview

  • Corporate website for Pro Document Services (PDS), a CCM / Omnichannel customer-communication company
  • Two deliverables: a full marketing site (index.html) and a standalone Excel/CSV upload tool (import-dat.html)
  • Upload micropage built to match a Figma spec, node-by-node, across all interaction states
  • Delivered as self-contained HTML/CSS/JS, no build step required

Project Summary

  • Hero, full-bleed video, news, contact, and footer sections, in that order, with a shared design language
  • Trilingual UI (Czech / English / French) via a single JS dictionary, switched instantly with no reload
  • Light and dark mode, toggled via CSS custom properties
  • Click-to-scroll hero CTA that autoplays the embedded YouTube video only once triggered
  • Import micropage: drag-and-drop upload, client-side file verification (sheet/row counts via SheetJS), error and success states, GDPR consent
  • Floating "back to top" control, favicon set, fully responsive

Your Role and Duration

  • Role: front-end implementation and content strategy, AI-assisted build (Claude as build partner)
  • Scope: markup/CSS/JS authoring, Figma token extraction, real content sourcing, QA
  • Duration: multi-session iterative build, delivered in incremental, reviewable commits
  • Tools: Figma MCP, headless-browser testing, web fetch for content sourcing, Pillow for asset generation

The Problem

  • The site launched with generic placeholder copy that didn't reflect the client's actual CCM/Omnichannel business
  • The data-import flow needed to match an existing Figma design exactly, including every state: idle, drag-over, error, verified, success
  • Content had to work identically across three languages without duplicating markup per locale
  • Several real UX bugs surfaced only under specific conditions: stacking-context conflicts, a third-party video embed error, imprecise anchor scrolling, low-contrast mobile navigation

Goals

  • Replace all placeholder copy with the client's real positioning, contact details, and news
  • Pixel-faithful translation of the Figma upload flow into working states
  • One dictionary-driven i18n system, no per-language page duplication
  • Consistent, accessible light/dark theming across both pages
  • Exact, offset-free scroll behavior for every in-page anchor
  • Graceful degradation when third-party scripts fail to load
  • Ship early, fix fast through targeted, verifiable iteration

Design Process

1. Discovery & content strategy

  • Fetched the client's live website to source real copy: address, phone, email, positioning, and news headlines
  • Identified the company's actual business (Omnichannel customer communication / CCM) and rewrote hero, footer, and news content in all three languages to match
  • Replaced every placeholder detail (address, contact info, taglines) with verified, real information

2. Component-driven design, sourced from Figma

  • Pulled the Excel-upload micropage node-by-node via Figma MCP: sidebar stepper, dropzone, file card, error banner, success view
  • Extracted actual color tokens, spacing, and typography from the file instead of approximating from screenshots
  • Rebuilt each interaction state (idle, drag-over, unsupported file, verified, submitted, success) to match the spec exactly

3. Core interaction design

  • Built a single dict object driving CS/EN/FR text via data-i18n attributes, swapped with no page reload
  • Light/dark mode via CSS custom properties toggled on the root element, no duplicated stylesheets
  • Hero CTA that scrolls to the video section and sets autoplay=1 on the iframe synchronously within the click handler, so playback only starts on user intent
  • Drag-and-drop upload with real client-side verification: file extension check, then SheetJS parsing for sheet and row counts
  • Floating "back to top" button, hidden by default and revealed via an IntersectionObserver on the footer

4. Visual refinement, bug-driven

  • Fixed a stacking-context bug where the mobile flyout menu rendered behind the hero content, by isolating the topbar into its own higher z-index context
  • Fixed a YouTube "Error 153" embed failure by switching to the privacy-enhanced domain and setting an explicit referrerpolicy
  • Fixed imprecise anchor scrolling: replaced CSS scroll-margin-top–based jumps with a computed getBoundingClientRect() + scrollTo, applied generically to every in-page anchor
  • Fixed low-contrast mobile navigation: solid dark background, larger and brighter link text, clear hover state
  • Fixed a footer email link overflowing its container on small screens with overflow-wrap
  • Reordered mobile header controls (logo → language → theme → menu) via flex order, without touching DOM structure

5. Verification

  • Every fix checked with automated headless-browser testing before being called done, not just visual review
  • Verified computed scroll positions, class states, and stacking order directly rather than assuming CSS intent matched output
  • Ran the full upload flow (idle → error → verified → success) end-to-end, including a graceful fallback path when the verification library fails to load

6. Assets & handoff

  • Generated a full favicon set (SVG source, multi-size PNGs, ICO) from the brand mark using headless-browser rendering and Pillow
  • Wired favicons and consistent metadata into both the main site and the import micropage
  • Kept both pages content-consistent (contact details, branding) after every real-content update
